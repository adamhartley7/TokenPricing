⚠ Live Sandbox Escape — Caught by Opus Review

Pipeline A's Opus review identified a genuine security-critical bug in the DeepSeek-generated code:

// DeepSeek generated:
path.resolve(allowlistDir, userPath)

// Opus review caught:
path.resolve does no filesystem resolution —
a symlink inside the allowlist escapes the sandbox.
Fix: fs.realpath for canonical
resolution + path.relative belt-and-suspenders.

DeepSeek's own self-review (Pipeline B) was completely empty — it produced no review text at all. The security vulnerability would have shipped uncaught in a DeepSeek-only pipeline.

Why This WILL Work (The ELI5 Version)

Imagine you asked someone to bake you a cake.

Pipeline A is like having a master chef (Opus) write you a recipe, then a fast kitchen assistant (DeepSeek) bake it, then the master chef taste it. But you only gave the assistant 3 minutes (4,096 tokens) to bake. They put the batter in the oven and… time's up. You got half-baked cake batter. The master chef tasted it and said "this is raw — 40/100."

Pipeline B is like having the kitchen assistant do everything alone — recipe, baking, tasting. But they don't know what a good cake tastes like. They gave you a shopping list and a bowl (types and config) and said "here's your cake!" The self-taste-test was just silence. 22/100.

The fix: Give the kitchen assistant 20 minutes (16,384 tokens) instead of 3, split the baking into two rounds (core first, frosting second), and always have the master chef taste it (Opus review). That gets you to 80.

To reach 85: Have a food safety inspector (security-only Opus audit) check the cake separately from the taste test. Different person, different checklist. Catches things the taste-tester wasn't looking for — like "this cake pan has sharp edges that could cut someone."

To reach 90: Have the master chef check that the recipe, the batter, AND the frosting all work together (integration audit). The recipe says "add 2 eggs" but the batter instructions say "add 3 eggs" — a per-step reviewer misses this. The integration audit catches it. The last 5 points require you to taste the cake and say "yes, this is what I wanted." No model can do that.

Why I know this works: We already proved the core pattern. Pipeline A scored 40 with the recipe half-written and the cake half-baked. The 60 missing points are ALL from fixable things — not enough time to finish writing code, not enough workstreams, no tests. Every single lost point has a known fix. We're not guessing about a new approach. We're removing the handcuffs from the approach that already worked.

Path to 100/100 — The Human Ceiling

95→100 is fundamentally different from every tier below it. The first 95 points are about what an automated pipeline can produce. The last 5 require a human.

PtRequirementWhy no LLM can do it
96 Real filesystem testing An LLM can write a symlink test. It cannot create an actual symlink on an actual filesystem and verify the sandbox blocks traversal. This requires a real OS. The test code it generates is a simulation — a real symlink has OS-level behavior (junction points, NTFS reparse points, race conditions) that no text prediction can verify.
97 Permission edge-case testing "What happens if the allowlist directory is deleted mid-operation?" "What if two agents try to write the same file?" These are race conditions and edge cases that require a running system. An LLM can theorize about them — it cannot discover the ones it didn't think of.
98 Human code review sign-off Opus reviewed the code. But Opus is a model — it hallucinates reviewed files (as seen in Pipeline A, where the review referenced sandbox.ts which wasn't in the build). A human reviewer catches this. No LLM review is a substitute for human review on security-critical code.
99 Deployment validation The code works on paper. Does it work in the 7C's app, on Windows 11, with the actual spend-guard gateway? Only running it live answers this. The pipeline can't deploy itself — that's a destructive action it's explicitly designed to prevent.
100 User says "this is what I wanted" The task description said "Build a Cowork tab." Did the pipeline build the Cowork tab you meant, or just the one you described? Only you can answer that. 100/100 means the human and the machine agree: the output matches the intent, not just the spec.
